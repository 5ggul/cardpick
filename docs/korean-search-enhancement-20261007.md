운영 원본 저장소와 기존 사용자 변경은 건드리지 않았다.

## 범위와 영향

- `search-query.mjs`: 공통 검색어 정규화, 검색용 한국어 별칭, 관련도 정렬, 검증 가격 선택. 완전한 한국어 도감이나 카드 메타 DB를 생성한 것이 아니다.
- `search.js`: 기존 classic 스크립트를 유지하며 첫 검색 때만 공통 모듈을 import한다. 15개 소비 소스의 HTML/script 태그를 바꾸지 않았다. 200장 조회/50장 표시 상한과 포켓몬 대상은 유지한다.
- `functions/search.js`: 카탈로그 GET 검색도 같은 정규화·관련도·가격 규칙을 사용한다. 원검색어는 화면과 링크에 유지한다. 200장 조회/60장 표시 상한은 유지한다.
- 별칭은 기존 사전을 이관하고 중복 키를 정리했다. `코코리=Phanpy` 추가, `에브이=Espeon` 및 `콘팡=Venonat` 수정. 잘못된 `윙크` 및 근거 없는 `에이브이` 오매핑은 제거했다. 나머지 기존 별칭의 전체 재검증을 했다는 뜻은 아니다.
- 겹치는 이름은 긴 이름부터 한글 단어 경계로 치환한다. `뮤츠 ex`, `메가리자몽 X ex`, 여러 별칭, 붙여 쓴 `코코리205`를 처리하고 `커뮤니티` 같은 다른 단어 속 이름은 치환하지 않는다. 한 글자 공식 이름 `뮤`는 헤더에서 검색할 수 있다.
- NFC 정규화 후 80자/최대 5토큰 제한. 알려지지 않은 한글은 추측 번역하지 않는다. 별표는 구분자로 처리하여 wildcard-only 입력이 전체 카탈로그 조회로 이어지지 않는다. SQL LIKE의 `%`, `_`, 역슬래시는 이스케이프한다.
- 늦은 카드/가격 응답, 입력 삭제·Escape·바깥 클릭은 결과를 다시 열거나 최신 검색을 덮지 못한다. 같은 입력 재포커스를 허용한다. IME 조합 중 조회·Enter 이동을 막고 조합 종료 후 검색한다.
- 검색 실패와 실제 0건·가격 필터 0건을 구분한다. 불러오기 오류에서 '미등록 카드' 또는 요청 접수 완료로 단정하지 않는다. 가격 필터만으로 0건이 된 경우 검색 로그도 생략한다. 기존 search-log API가 간접 업데이트 RPC를 호출하기 때문이다.
- 검색 가격은 `card_price_trust`의 HIGH/MEDIUM/LOW 및 유효한 양수 `display_krw`만 쓴다. NONE·누락·알 수 없는 등급·오류에서는 raw 가격으로 대체하지 않는다. LOW에는 표본 부족 표시. 카드 조회가 성공하고 가격 조회만 실패하면 카드 링크는 남긴다.
- localhost/127.0.0.1/IPv6 loopback에서는 운영 검색 로그·업데이트 요청을 보내지 않는다. 운영의 기존 성공 검색 기록 및 실제 0건 처리 경로는 유지한다. DB 데이터·RLS·schema·API 권한은 변경하지 않았다.
- SSR inline JSON의 `<` 이스케이프, 검색 입력 접근성 이름, 검색 페이지 소유 모바일 헤더 줄바꿈을 보완했다. 가격 산식·URL·canonical·robots·사이트맵·카드 색인 게이트·기존 광고 정책은 변경하지 않았다.
